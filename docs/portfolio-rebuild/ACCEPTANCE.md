# 验收：视觉、探索、工程、传播分别过关

配套版本：MASTER_BRIEF.md v1.1 / HERO_SCENE_SPEC.md · 2026-09-25
状态：待执行。所有勾选、实测数字和证据需由 Codex 实际执行后填写。

## 1. 验收的三个层次

交付质量：现在就能检查的首屏、交互、经典版保护、内容、手机、性能和传播物料。
体验证据：目标用户是否愿意继续看、是否主动探索、是否记住赵越，以及能否快速找项目。
业务结果：发布后的相关面试、合作交流与真实成交，不能在部署成功当天宣称已经实现。

发布的最低条件是关键交付项通过且没有明显体验阻断。通过验收不等于保证爆火；流量和机会用后续真实记录验证。

## 2. 视觉门槛：必须真实看图，不用测试脚本代替

| 编号 | 检查项 | 通过标准 | 证据 |
|---|---|---|---|
| V01 | 静止首帧 | 不移动鼠标、不播放片头，画面已完整；没有大片空白、百分比或廉价草模 | 桌面/手机实际网页截图 |
| V02 | 构图主次 | 可以指出主视觉、第一操作对象、空间层次；不是一排等权屏幕或卡片 | 截图与简短评审 |
| V03 | 材质与光线 | 金属、纸、唱片、屏幕有区别；物件不悬空穿插；关键内容没有被黑暗吞掉 | 局部特写与网页全景 |
| V04 | 作者性 | 有真实个人作品与细节；去掉 Logo 后仍不是通用 SaaS/AI 模板 | 与目标图对照、用户观察 |
| V05 | 文字与导航 | 姓名、角色、版本切换、项目、简历和联系清楚；不靠读长文理解 | 首屏与导航近景 |
| V06 | 动作完成度 | 第一次点击有及时反馈、过渡有始终状态；没有弹跳穿模、相机跳切、音画错位 | 一镜到底真实操作录屏 |
| V07 | 视觉目标一致 | 网页的模型、相机、灯光、色彩达到经批准目标；概念图不能冒充实现 | 同视口对照 |
| V08 | 手机与竖屏 | 重排构图，不把桌面压成缩略图；主要物件看得清也点得到 | 390×844 / 9:16 素材 |
| V09 | 可传播画面 | 至少一张可独立用作封面的静态画面，以及一个可单独看懂的动作 | 真实版本封面与短片 |
| V10 | 人工批准 | 赵越明确确认首屏和标志性互动的版本 | 批准记录或具体修改意见 |
| V11 | 完整三维室内 | 人物、桌椅、屏幕与环境形成真实空间，不是俯视空桌、图片视差或循环视频 | 实际网页、微小机位变化或必要场景调试证据 |
| V12 | 本人角色 | 坐在桌前、外貌/造型来源明确且经本人确认；不使用参考图人物/通用占位冒充 | 素材授权记录、人物近景、全景和确认版本 |
| V13 | 人与场景关系 | 人体、手、脚和家具无明显穿模；人物可辨认，脸与屏幕不互相完全遮挡 | 正常首屏与角色接触处近景 |
| V14 | 底部模式胶囊 | 交互版/经典版两态，底部居中，两版一致，独立于 Canvas，手机不遮挡 | 两版首屏、手机与错误状态截图 |
| V15 | 参考迁移而非复制 | 保留空间与人物机制，使用赵越的造型/作品；不复制 Basement 人物/海报/品牌 | 对照图与素材登记 |

V01、V03、V06、V07、V10、V11、V12、V13、V14 未通过，不能称为最终视觉。不要用“风格比较主观”逃避明显的材质、构图与完成度问题。

缺本人照片时 V12 及综合本人首屏验收必须标记“阻塞/待确认”，允许继续中性占位的内部构图与流程测试，但不称最终完成。

## 3. 最小交互路径：逐项操作

| 编号 | 测试操作 | 预期结果 |
|---|---|---|
| I01 | 冷启动进入交互版，不移动鼠标 | 场景或可信的精制首帧可见；经典版/项目/联系不被加载遮罩挡住 |
| I02 | 鼠标点击唱片机 | 可见反馈；正确音乐内容打开；不需要双击、驾驶或教学 |
| I03 | 手机直接点击同一物件 | 不依赖 Hover；内容可读，关闭和返回可见 |
| I04 | 打开书、关闭、再打开另一本 | 内容对应正确；相机、选择状态、焦点没有错乱 |
| I05 | 音乐主动播放、暂停、切曲 | 同时最多一条实际播放流；按钮与真实播放状态一致 |
| I06 | 模拟音频失败或播放被拒绝 | 有反馈和可用外链/重试；页面不崩溃，不显示假播放 |
| I07 | 主动选择进入 MV，再返回 | 动作与已批准分镜一致；可以跳过大转场；返回正确位置 |
| I08 | 从 Finfold 物件进入完整项目 | 打开对应真实页面；角色与内容一致，不绕回首页 |
| I09 | 交互版切经典版再切回 | 经典版完整可用，状态合理恢复；不重复音乐或留下遮罩 |
| I10 | 使用浏览器返回/前进 | 没有循环跳转、重复历史堆栈或丢失主要内容 |
| I11 | 分享某本书/作品的深链接，新窗口打开 | 直接定位对应内容；不要求从头找路；不存在 ID 时友好处理 |
| I12 | 连续快速切换 5 次物件或打断转场 | 不出现两个面板重叠、旧音频继续、镜头卡住 |
| I13 | Tab、Enter/Space、Esc | 关键功能可操作；焦点可见，面板关闭后返回合理位置 |
| I14 | 只想看简历或联系 | 不必探索即可直达；联系方式来源可靠 |
| I15 | 开启减少动态效果 | 取消大幅镜头运动，内容、切换和返回仍完整 |
| I16 | 首屏已显示人物但模型/音乐仍在加载时切经典版 | 胶囊立即有效，不等待人物或相机动画 |
| I17 | 人物待机循环中打开内容与切模式 | 动作不抢焦点、不穿模、不自动开声音；切出后停止不必要更新 |
| I18 | 手机打开面板、滚动正文、旋转设备 | 胶囊与安全区正确，不遮盖关闭、播放或最后一段正文 |

自动测试可以使用与真实场景对应的语义热点；不能只测试一套不参与真实使用的隐藏按钮，然后宣布三维交互通过。

## 4. 经典版回归与数据真实性

- 记录本次修改前实际存在的路由、锚点、项目、简历、媒体、联系方式与语言行为。
- 新旧关键路径逐一核对，不能只测首页 HTTP 状态。
- 经典版不无条件下载整套三维资源；新资源报错不应破坏经典版。
- 原有框架、构建和部署未被无理由替换；用户既有未提交改动未丢失。
- 同一项目在两版的名字、角色、状态、封面和链接一致。
- 每个新增业绩数字可追溯到来源和口径；平台规模与个人贡献分开。
- 书单、音乐感受、摄影、个人经历和评价均有真实来源。
- 本人肖像和服装参考经确认；用户提供的他站场景图不被当作赵越照片、本站作品或可复用纹理。
- 版权/许可/脱敏待确认项没有被偷偷转成“已确认”。
- 演示或概念内容明确标注，不把概念界面包装成客户已上线功能。

## 5. 性能：不能只看加载分数

### 必须记录测试条件

浏览器与版本、系统、设备或模拟配置、窗口与像素比、网络下行/时延、缓存状态、构建模式、当前提交、测试日期。至少包含冷启动与复访，生产构建与开发服务器结果分开。

### 项目自定义指标

- `scene_first_frame_ms`：用户真正看到目标场景/明确的场景封面的时间；记录类型为 poster 或 rendered。
- `hotspots_ready_ms`：至少一个有真实内容的热点可以成功打开的时间；不能仅以按钮已出现判断。
- `scene_interactive_ms`：核心三维场景能接收并完成代表性交互的时间；不能用静态封面时间替代。
- `first_meaningful_action_ms`：访客第一次主动打开真实内容/项目的时间；播放开场不算用户行为。
- `fallback_type`：none / lightweight_scene / classic_link，说明是否降级。

“三秒目标”用这些分开的指标观察。慢网下完整三维没有三秒可用，就如实报告并给出可操作的轻量入口；不要伪造计时起点。

### 项目预算与通用标准分开

首屏核心三维传输预算、设备帧率和测试人数都属于本项目建议，可根据实测调整并记录理由。v1.1 的房间、本人角色、贴图和解码器分别计入加载；v1.0 的 3–5MB 只作旧估算，更新预算须透明确认，不删人物来卡数字。Core Web Vitals 的 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 来自官方资料，按现场第 75 百分位评估；实验室数据不能冒充现场结果。

来源：https://web.dev/articles/vitals

### 必测故障与压力

- 模型、纹理、音频、视频任一加载失败。
- WebGL 不可用或上下文丢失：保留内容入口与返回方式。
- 弱网络、离线重访、外部播放器不可达。
- 前后台切换：不持续无意义渲染、不自行恢复声音。
- 交互版与经典版往返 10 次：不累积音轨、事件监听、Canvas 或明显持续增长的资源占用。
- 手机横竖屏切换、浏览器工具栏改变可用高度。
- 中文/英文与较长项目标题：不溢出遮挡。

帧率和资源占用记录实测条件及波动，不能把一次瞬时值当稳定结果。性能优化前后各留同一机位截图，确保没有把视觉质量偷偷降低到未批准状态。

## 6. 建议的截图与录屏证据

至少保存：
1. 桌面首屏 1440×900。
2. 小桌面首屏 1280×800。
3. 手机首屏 390×844 与窄屏 360×800。
4. 唱片交互默认、打开、播放/失败、进入现场与返回。

8. 减少动态效果状态。
9. 一段不剪辑的完整主要路径录屏。
10. 本人角色近景、坐姿与桌椅接触、在场景中实际待机。

## 7. 小规模用户测试

建议邀请 8–10 人，覆盖目标招聘/产品设计负责人、潜在客户和普通内容观众；不要全由开发者同事组成。无法邀请时明确标记“未进行用户测试”，不能用 Agent 扮演用户的推断代替。

步骤：
- 短暂展示首屏后移开，问记住了什么、觉得可以做什么、想不想继续看。可采用约三秒展示作为项目诊断，不声称是研究定律。
- 恢复页面，不提示，让其自由探索。记录第一次点击、犹豫、误点、主动打开第二个内容的情况。
- 单独给任务：“找一个相关项目”“找简历”“切回普通浏览”，观察是否需要帮助。
- 看完后问最有印象的内容，以及认为赵越主要做什么。

建议内部检查线：多数参与者无需讲解完成第一次操作；没有人被主要导航困住；多数人能记住一个属于赵越的内容而不仅是特效；目标招聘/客户能独立到达项目与联系。

可记录人数和原话，不伪造百分比提升。小样本用于发现明显问题，不代表统计显著结论。

## 8. 测量事件定义

| 事件 | 触发 | 不代表什么 |
|---|---|---|
| experience_view | 某模式实际可见 | 不等于认真看完 |
| scene_ready | 实际核心三维可交互 | 不包含仅显示占位图 |
| object_open | 用户主动打开有真实内容的物件 | 不是每一帧/每次 Hover 都记一次 |
| project_open | 对应项目内容实际呈现 | 不等于认可能力 |
| mode_switch | 用户显式切换模式 | 不把强制降级算主动选择 |
| resume_open | 简历页面/资源打开或跳转被发起，注明类型 | 不一定完整下载/阅读 |
| contact_intent | 点击邮件、联系或咨询入口 | 不等于消息发出或有效线索 |
| contact_submit_success | 仅限有后端确认成功的真实表单 | mailto 跳转不能触发此事件 |
| share_intent | 打开分享操作 | 不等于已分享 |
| link_copied | 复制成功 | 不等于朋友访问 |
| share_api_resolved | 系统分享调用成功返回 | 不作为实际转发/收件人数证据 |
| qualified_conversation | 真实记录确认的相关求职/合作交流 | 不是自动点击事件 |

建议记录模式、内容 ID、语言、设备类别、版本及允许的来源参数；不要记录私人文本、邮箱内容或其他不必要个人信息。遵循站点既有隐私与同意机制，不为此临时堆追踪工具。

漏斗按渠道、受众意图和版本分别看。已有经典版流量是对照线索，但不直接与不同来源的新站宣传流量做因果比较。停留只统计实际可见的活跃时间并结合行为解释。

## 9. 发布素材验收

- 短片开头直接有画面和操作，没有冗长 Logo/自我介绍。
- 核心动作在静音下仍能看懂，字幕不遮住物件与按钮。
- 竖屏为专门构图，横屏不直接被切掉关键信息。
- 录屏对应本次实际版本；剪辑不伪造交互、用户量和功能。
- 至少一个片段看完后能说清“这个网站有什么特别”。
- 至少一段清楚展示赵越本人在工作台前和物件探索，不用仅有空桌或他站素材充当首发镜头。
- 中文字幕自然；英文标题、字幕独立检查，不夹杂错误占位。
- 两张封面候选、首页/重点深链接预览清楚；姓名和网站地址准确。
- 音乐、影像、模型与图片的公开发布使用范围已经核实。
- 未获授权不发布小红书、YouTube，不购买流量，不自动提交奖项。

## 10. 上线门槛和回滚

P0/P1/P2/P3/P4 的关键阻断项关闭；用户确认视觉与上线。记录此次是否仅发布 `/explore`，或同时调整根入口。没有批准就保留预览。

预览页的 noindex 不得误加到生产全部页面。现有项目、简历、联系、语言、分享链接发布后再检查一次；保留与现有栈匹配的可回滚版本和资源。

上线报告分开写：已交付、已测试、未测试、真实指标、用户反馈、业务结果。不能在“已部署”后直接写“高流量重构成功”。
