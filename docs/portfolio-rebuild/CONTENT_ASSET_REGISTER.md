## 2. 每件内容的记录字段

建议数据结构，不要求迁移现有内容系统：

- `id`：稳定内容 ID，两版共用。
- `type`：project / book / music / photo / writing / profile。
- `title`、`summary`、`locale`：展示内容，不自动创造个人感受。
- `source`、`sourceDate`、`verifiedBy`：内容来自哪里、何时确认、由谁确认。
- `status`：draft / verified / published / needs_review。
- `canonicalUrl`：实际存在的详情路径；待建路径单独标注。
- `sceneObjectId`：对应的三维对象或语义热点，不与内容正文绑定。
- `coverAsset`、`mediaAsset`、`sourceAsset`：封面、网页媒体、可编辑原文件。
- `rightsStatus`：unknown / approved / licensed / link_only；必要时记录范围与到期条件。
- `isPublic`：未经确认的私人内容与示例占位必须为 false。
- `notes`：缺口、脱敏、功能状态、外链限制。

## 4. 三维资产记录

| 字段 | 要求 |
|---|---|
| asset_id / scene_object_id | 语义稳定，避免全是 Cube.001 |
| origin / license | 自制、来源、许可与使用范围 |
| editable_source | Blender 源文件或其他实际可编辑工程 |
| generator | 使用的脚本/参数；无脚本时写明制作方式 |
| web_export | 实际 glb/gltf 与关联纹理 |
| dimensions / pivot | 场景尺度与旋转中心 |
| named_parts | 唱片、唱臂、书封、角色网格/骨架等独立部件 |
| avatar_reference / approval | 本人肖像来源、服装/外貌确认、占位或最终状态 |
| cameras / animation_clips | 实际包含的镜头与动作 |
| compressed_bytes / triangles | 测量值，不填预估冒充实测 |
| dependencies | 解码器、字体、纹理、HDRI 等 |
| browser_verified | 在何种真实环境查看过 |

只交 glb 不交可编辑来源，后续就难以改变书本、封面与唱片动作。两种形式都要保留；不要把无法编辑的第三方资产声称为自建模型。

## 5. 真实缺口怎么处理

能够从仓库解决的先解决。缺本人偏好、未经授权照片、业绩证据或账号信息时，记录准确缺项，不编造；优先继续模型、布局、状态与已确认素材的工作。没有本人肖像时用明确的中性坐姿占位推进室内和相机，不生成声称像赵越的脸，也不把要求有人物的方案退回空桌。

内部原型可以使用明确的中性占位，但占位不进入生产发布，不能在截图中被包装成最终个人内容。必要时只隐藏未准备好的内容入口，不留下大量打不开的装饰物。

## 6. 第一轮反馈格式

已找到：列出真实路径与可用状态。
可直接使用：说明已经确认的内容与许可。
需处理：列出裁切、压缩、脱敏、转码、封面制作等实际工作。
需用户补充：仅列无法从现有资料获得的具体项。
仍可推进：说明不依赖缺项的工作，避免整个项目因一张照片停摆。
