01 / THE QUESTION

很多事情，
总要等回到电脑前。

路上想起的一个待办，开会时冒出来的一个想法。记下来以后，还要再找回来、解释一遍，再打开工具去做。我们想把这个来回缩短。

AG05 / INPUT TERMINAL

我们使用 AG05 和厂商 SDK，把重点放在它后面的体验。眼镜采集声音，手机承接对话，小觅把请求带入同一个 MissionGet 工作台。

  1. 眼镜 · 采集
  2. 手机 · 对话与确认
  3. 工作台 · 执行与文件

眼镜作为输入终端；任务与成果留在 MissionGet。

02 / THE FIRST FRICTION

连上眼镜，
事情还没开始。

第一版已经能录音、识别文字。可说完一句话，仍要在手机上结束录音、发送，再找任务入口。手空出来了，操作还跟在后面。

说完以后，为什么还要一直点？

“已连接”之后，还有几步。

控制连上了，不等于麦克风已经准备好。收到文字，也不代表任务已经执行。每个状态都得让人知道，刚刚发生了什么，接下来由谁接手。

  1. 01连接眼镜
  2. 02听见指令
  3. 03核对请求
  4. 04交给工作台

03 / THE DESIGN DECISION

把操作重新安排，
让对话接下去。

短指令停顿后结束，回复后继续听。会议录音则走独立入口，保留录音和转写。真正会改动任务的动作，仍然停下来，请人确认。

操作流程复原
  1. 01说出需求
  2. 02停顿后识别
  3. 03小觅接话
  4. 04核对并确认

把录音结束和继续接话交给系统，把业务决定留给人。

少一点手机操作，
保留那个该由人决定的时刻。

05 / BACK TO THE REAL PRODUCT

同一个 MissionGet，
就该是同一份工作。

另做一个任务页面很快，接回真实工作台却要继续处理账号、消息和文件。我们把手机端放回原有产品里，让小觅的对话和电脑端的任务能互相接上。

去掉重复的网页导航和小觅浮窗，沿用同一账号。手机发起的请求，能在电脑的工作台找到；确认后的文件，也回到同一份任务里。

这一次，文件出现在了另一端。

07 / STILL IN PROGRESS

下一步，
再少碰几次手机。

这次整合把语音、手机与工作台接得更近。眼镜实体按键的照片回传仍未完成本轮验收，前台语音对话也有使用条件。接下来的工作，是让这些边界变得更清楚、更稳定。

这次设计一直做到界面之外。
连上、听见、确认、执行，每一步都需要被接住。

看整合背后的三个判断 +

先拆清眼镜控制与音频连接，再分别处理录音和播报；区分短指令与会议录音；复用官网账号与任务文件，保留业务确认。这个案例呈现的是设计与原型整合过程，不宣称眼镜硬件由我设计，也不将固定演示写成线上执行。
